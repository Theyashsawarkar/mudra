Changelog

Every change to mudra, newest first. Releases are git tags (all tags, GitHub releases); the source of this page is CHANGELOG.md.

v0.7.02026-11-28Release notes

  • Reopening is quick again: the bindings are read again behind the panel only when the last read is older than reload_after seconds (default 120), a second after the panel shows, instead of on every open. The read is ~2 s of CPU (every config, a throwaway tmux server), and parsing its answer inside Vyom held up the panel's first frame: reopening took 50-180 ms, now 15-25 ms (with Vyom 0.11's kept rows).
  • Website: pranali joins the family list in the footer; the site builder passes ruff.
  • New screenshots in the Spatial look, taken with made-up demo data (WebP, sharp on high-density screens).
  • The website, closer to Vayu's own: the tool's screenshot blurred behind the page, a centred hero with the logo and the verse, the page you're on as the white pill, glass "On this page" and footer panels, releases as cards. No glow behind the logo, no coloured line beside the verse.
  • Spatial look: app chips are pills; the preview's key caps are glass, and the leader key is filled near-white.
  • The website has Vayu's Spatial look: graphite glass, a floating navigation bar, near-white for links and the main button, and the tool's own colour only as its signature (the logo's glow, the shloka's line, the release dots). No more all-caps labels.

v0.6.12026-11-14Release notes

  • No full read of every keybinding when Vyom starts. It took 1.6 s of CPU in the middle of the login rush, while the first panels and apps were starting. The last read is kept on disk (~/.cache/vyom/mudra-keybinds.json) and loaded at once; the full read follows a minute later. Opening the panel re-reads in the background, as before. The first run ever (no saved read) still reads right away.

v0.6.02026-11-09Release notes

  • Space u p (show or hide the preview) now comes from Vyom core, which also remembers it per tool; the tool's own copy is gone.
  • Vim keys (Vyom 0.7, ADR 0008): NORMAL and INSERT modes, Space as the leader with a which-key strip, ? and Space ? list every key, Space Space is a palette, counts (5j), gg / G, H / L for tabs. It opens in INSERT (search-first): type, then Esc for NORMAL. Needs Vyom 0.7.0.
  • Its keys are data (mudra/vim.py); scripts/keybinds.py writes the # keybind: lines and the README's key tables from them, and --check (CI) fails when they drift.
  • y y copies the keys (Ctrl+C still does in NORMAL), o opens the file that defines a key in $EDITOR at its line, Space f c shows only clashes, Space f m one mode, Space f d hides built-ins, Space f k searches by keys (dd, gg), Space f l the Leader tab, Space y d / Space y c copy the description / command, Space r reads every key again.
  • Vim and leader keys, for tools that follow the Space grammar (Vayu's docs/KEYBINDINGS.md): bare letters keep their case (g g and G no longer look alike), a leader sequence shows as caps joined by › with the Space cap in the accent, and rows carry neutral normal / insert and leader chips (keybind-search.py now sends mode, leader and group).
  • space y searches by sequence, in order (spc y, <leader>y too): the whole group under it, shortest first. The preview shows the which-key path with group names.
  • A Leader tab with every Space key of every tool. Clashes now count per mode, include a key that starts a longer one (g beside g g), and, in the Leader tab, a shared leader group used for something else.

v0.5.12026-11-08Release notes

  • Vyom is one group with a section per tool (Vyom · ganit, Vyom · tarang…), every panel's own keys first, each section noting what the tool is (Calculator, Wi-Fi…). A row says which tool and part it belongs to (ganit · converter), and a tool's name or title finds its keys: "ganit", "calculator", "tarang enter". Needs keybind-search.py to tag Vyom keys with their tool (Vayu dotfiles, 2026-11-08).
  • Tabs show the app's name only; its count is in the tooltip and on its sections.

v0.5.02026-11-07Release notes

  • A new look (Vyom 0.6): each row starts with its app as a coloured chip, always the same colour for the same app; the words you searched for are peach; the keys sit at the right as real key caps, chords joined by "then".
  • Clashes: a key bound twice in the same app and scope (in your own configs) gets a red "Clash" chip, and the preview says what else it does.
  • Tabs with counts ("Sway 106") on the biggest apps; at most ten tabs, so Ctrl+1..9 and Ctrl+0 reach every one: the smallest apps share "Other".
  • The preview shows the keys as big caps, where the binding is defined (file and line for sway, kitty and zed; the file for a tool's own keys), what it does, and a Run it (Enter) and Copy keys (Ctrl+C) button.
  • Needs Vyom 0.6.0.
  • Every corner is rounded: the website's callouts.
  • A logo and a shloka at the top of the README and the website: every Vayu tool has them now.

v0.4.02026-11-02Release notes

  • Opens at once. It read every config on each open, a blank panel for several seconds. Now it reads ahead when Vyom starts, opens on what it knows, and catches up behind the panel. A failed read keeps what it has instead of falling back to Sway's keys only.

v0.3.12026-10-24Release notes

  • pramana's keys (the polkit password prompt) show with their own colour and a lock icon.

v0.3.02026-10-24Release notes

  • Search by keys: a query that names a modifier (ctrl+h, super q, alt 1, prefix s) finds the bindings with those keys, exact ones first; a capital letter counts as Shift.
  • Every word on its own, in any order, and the app's name is searchable: "tmux kill" finds tmux's kill bindings (it found nothing), "wifi" finds Wi-Fi. Words as written rank first; loose matching ("vol" in "quick settings") no longer pulls in noise.
  • Ranked, not grouped, while searching: one list, best match first, the app as a badge on each row (grouped by app only with an empty box). The best match used to sit in whichever app group came first.
  • Tabs numbered (Vyom 0.4.0), most bindings first, all of them: the app you jump to most gets the low number, and none is left out (it stopped at nine apps).
  • Key caps in the theme's colours (they were fixed Catppuccin); "or" between alternatives (Ctrl+Tab or Ctrl+Shift+Tab) instead of a "then" chord.
  • Icons and colours for nāda, vesha, vinyasa and anumati bindings.

v0.2.02026-10-24Release notes

  • App tabs switch like every Vyom tool's tabs (Vyom 0.3.0): Ctrl+H / Ctrl+L for the previous / next app, Ctrl+1..9 and Ctrl+0 by number (now up to ten apps, was nine). Needs Vyom 0.3.0.

v0.1.22026-10-21Release notes

  • A website (GitHub Pages, https://theyashsawarkar.github.io/mudra/): the README as a home page, the changelog, and architecture decision records (docs/adr/), built from these files by scripts/build-site.py; CI checks the site is up to date.

v0.1.12026-10-21Release notes

  • Documentation for open source: a logo and banner, a full README (features, install, usage, configuration, troubleshooting, the whole Vyom family), CONTRIBUTING, SECURITY and CODE_OF_CONDUCT, issue and pull request templates, and CI (compiles, checks plugin.toml and that every key is documented).

v0.1.02026-10-19Release notes

  • First release, as its own repository: keybinding search. Replaces keybind-search.py's wofi popup in Vayu.
  • Every keybinding by what it does ("kill window", "volume"), with real key caps and chords (Ctrl A then &).
  • Grouped by app, with a tab per app (sway, tmux, kitty, zed, rmpc, Vyom…).
  • Enter runs the binding: sway ones through swaymsg, tmux ones replayed into your most recent tmux client; anything else copies its keys.
  • Bindings come from a command printing JSON (Vayu's keybind-search.py --json); without one it reads sway's own config.
